## Phase 3 — Les 6 nouveaux outils
Chacun : fichier tool + entrées dans `config.ts` (TOOL_IDS, TOOLS_META, TOOL_SYSTEM_HINTS) + `ChatTools` dans `lib/types.ts` + enregistrement dans `lib/chat/tools.ts` + carte dédiée dans `message.tsx`. Tous activables gratuitement via toggle (DEFAULT_ENABLED_TOOLS inchangé).

**3.1 `generateDiagram.ts`** — input `{title, format: mermaid|plantuml, code, description?}` ; sort `{id, title, format, code}`. Carte `components/chat/diagram-card.tsx` : rendu `mermaid.render()` (import direct ajouté au package.json), zoom/pan (pointer+wheel, sans lib), boutons zoom/reset/plein écran, vue code/rendu, **export SVG** (sérialisation) et **export PNG** (canvas). Erreur de syntaxe affichée avec repli code.

**3.2 `documentParser.ts`** — input `{url (blob public Vercel), maxChars?, extractTables?}` ; fetch du blob → routage par contentType : PDF via `pdf-parse` (texte + marqueurs `--- Page N ---`), DOCX via `mammoth` (→HTML→ texte, titres conservés), CSV via papaparse. `extractTables` renvoie les tableaux détectés en CSV ; le modèle peut les pousser dans un artefact sheet via `createDocument`. Retour `{content, pages, tables[], structure[], isTruncated}`. Carte : aperçu chapitres/tableaux + bouton « Ouvrir en artefact ».

**3.3 `audioPodcast.ts`** — le modèle fournit `segments[]` ({speaker: host|expert, text}, 1-40, ≤1200 chars/segment) + `{title, style?}`. Le tool vérifie le quota speech, récupère /v1/audio/voices pour choisir **2 voix distinctes** (fallback voix par défaut), synthétise chaque segment via `MAI_API_URL/v1/audio/speech` (séquentiel, arrêt gracieux si quota atteint), retourne `{id, title, segments:[{speaker, text, voice, audio_url}]}`. Carte `podcast-card.tsx` : lecteur rétro/moderne (play/pause, progression continue sur les segments, barres d'onde animées, sous-titres synchronisés, paroles affichées) — lecture séquentielle via un seul `<audio>` qui enchaîne les segments ; fonctionne après reload (sortie persistée dans les parts).

**3.4 `webCapture.ts`** — input `{url, includeScreenshot?}` ; extraction `isPrivateOrBlockedHost` mutualisée dans `lib/web/ssrf.ts` (extraite de read-url.ts, réutilisée par les deux) ; fetch HTML → métadonnées OpenGraph complètes, SEO (robots, canonical, viewport, lang, h1s), détection techno basique. Screenshot via service gratuit sans clé : `thum.io` avec repli `s0.wp.com/mshots`. `toModelOutput` multimodal (texte + image URL) pour que les modèles vision « voient » la capture. Carte : screenshot + tableau métadonnées.

**3.5 `calendarReminder.ts`** — input `{title, start (ISO), end?, location?, description?, attendees?}`. Génération **ICS sans dépendance** (`lib/ai/ics.ts` : échappement, pliage de lignes, UID, DTSTAMP) + liens préremplis Google Calendar et Outlook. Carte : boutons « Télécharger .ics » (Blob download), « Google Calendar », « Outlook ». Point d'extension noté vers `lib/planning/` (création de scheduledMessage) laissé hors scope.

**3.6 `cryptoTools.ts`** — outil unique multi-opérations (pattern calculator) : `hash` (sha256/sha384/sha512 via node:crypto), `bcrypt_hash`/`bcrypt_compare` (bcryptjs, rounds 4-15), `jwt_decode`/`jwt_verify_hs256` (jose), `generate_secret` (hex/base64, 16-128 octets), `regex_test` (matches + groupes + flag safety ReDoS), `sql_format` (sql-formatter, dialects principaux). Constante pure (pas de session/dataStream).
