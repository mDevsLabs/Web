# Plan — mAI Vibe : éditeur riche, mAI contextuel, planification, partage minimaliste

## Contexte
- Backend Hono/Deno au root (base Neon PostgreSQL, migrations appliquées de façon **idempotente au démarrage** comme dans `vibe-dms.ts:19-67` — le migrateur n'exécute pas les SQL). Frontend React 19 + Vite + Tailwind 4 dans `src/`. Dépendance `qrcode` déjà installée ; **aucun éditeur riche** → on utilisera un éditeur `contenteditable` maison basé sur `document.execCommand` (pas de lib lourde) + ajout de **dompurify** (sanitization XSS).

---

## Phase 1 — Éditeur WYSIWYG + Markdown + légendes Vibe
**Nouveau `src/components/common/RichTextEditor.tsx`** (contenteditable) :
- Barre d'outils B&W fixe : **B**, *I*, U (souligné), ~~S~~ (barré), liste à puces, liste numérotée, citation, lien (via `execCommand` : bold/italic/underline/strikeThrough/insertUnorderedList/insertOrderedList/createLink).
- **Barre flottante au survole de sélection** (même actions + ajout de lien) — positionnée au-dessus de la sélection.
- **Support Markdown en saisie** : `**gras**`, `*italique*`, `__souligné__`, `~~barré~~`, `- `/`1. ` → listes, `> ` → citation (règles d'input au frappe).
- **Collage d'URL** → popover minimal « Nom du lien » (ex. ICI) → insère `[nom](url)` rendu en lien cliquable.
- Auto-resize vertical, placeholder, API `ref` (getHTML/insertText/focus) pour garder la dictée vocale existante.

**Nouveau `src/components/common/RichContent.tsx`** (rendu) : sanitize HTML via DOMPurify, conversion @mentions/#hashtags/URLs en liens cliquables. Rétrocompatibilité : si le contenu ne contient pas de balises HTML (anciens posts), rendu hérité `FormattedText.tsx` inchangé.

**Intégrations** : `PostComposer.tsx` (textarea → RichTextEditor), `CommentSection.tsx`, rendu dans `PostCard.tsx` (posts + citations) et commentaires.

**Légendes d'images Vibe** : champ « Ajouter une légende… » sous chaque aperçu média du composer → envoyé en `alt_text` (colonne déjà en base, `vibe-posts.ts:605-650`), affiché comme légende visible sous le média dans `PostCard.tsx`.

## Phase 2 — Édition des Vibe
- Backend `vibe-posts.ts` : nouveau `PATCH /posts/:id` (auteur uniquement, validation longueur + sanitization, mise à jour contenu/médias/légendes, `updated_at`).
- Frontend : `ApiService.updatePost` (`src/services/api.ts`), menu auteur `PostCard.tsx` → « Modifier » (aux côtés de Supprimer), ouverture du composer modal en mode édition (contenu pré-rempli, bouton « Enregistrer »).

## Phase 3 — Images + légendes dans les commentaires
- Backend : colonne idempotente `comments.media jsonb` ; `POST` commentaire accepte ≤ **3 images + 1 vidéo** (50 Mo total, mêmes règles MIME que `storage.ts`) avec `alt_text` par média.
- Frontend `CommentSection.tsx` : bouton média + aperçus avec champ légende, rendu média + légende dans le fil de commentaires.

## Phase 4 — Planification de publication (Plus/Pro/Max)
- Schema idempotent : `posts.status text DEFAULT 'published'` + `posts.scheduled_at timestamptz`.
- Backend : `handleCreatePost` accepte `scheduled_at` (gate tier : Free → 403 `plan_required`) ; helper **lazy** `publishDuePosts()` (UPDATE → published + notification à l'auteur) appelé sur les endpoints de feed/profil — aucun cron nécessaire, pattern fiable ici ; requêtes de feed filtrées `status='published'`.
- Frontend composer : bouton horloge → sélecteur `datetime-local` stylé B&W ; Free = cadenas + badge « Plus · Pro · Max » (upsell) ; badge « Planifiée » visible par l'auteur sur son profil.

## Phase 5 — Plus de contexte mAI
- `vibe-mai.ts` `handleMAIChat` : persistance dans les tables `mai_conversations`/`mai_messages` (migration 002 existante, inutilisée) — 1 conversation active par utilisateur, injection des **~20 derniers messages** dans l'appel OpenRouter (+ contexte post existant). Nouveau `GET /v1/mai/history` pour recharger la conversation à l'ouverture.
- Frontend `MAIStudioPage.tsx` + `MAIDrawer.tsx` : chargement de l'historique au montage, envoi avec conversation persistée.

## Phase 6 — Compte mAI + réponses DM + usage hebdomadaire
- Seed idempotent au démarrage (pattern migration 005 du `@bot`) : user `mai` (email mai@vibe.ai, tier **Max**, is_verified, avatar dicebear bottts) + profile « mAI » + `user_settings` (allow_dms everyone).
- `vibe-dms.ts` `handleSendDM` : si destinataire = `mai` → génération de réponse via OpenRouter avec **historique de la conversation DM** (pattern du suggest-reply, `vibe-dms.ts:421-482`), insertion avec délai « en train d'écrire », **débit `weekly_usage` de l'expéditeur** (formule `max(75, (prompt+completion)/3)`). mAI apparaît naturellement dans la recherche DM et avec le badge vérifié.

## Phase 7 — Partage de profil minimaliste (B&W)
- Réécriture de `ProfileShareModal.tsx` (921 → ~250 lignes) : **une seule vue** = QR Code noir sur blanc (`errorCorrectionLevel: 'H'`, **logo.png `public/logo.png` dessiné au centre** sur pastille blanche arrondie) + bouton « Copier le lien » + bouton « Télécharger le QR Code » (PNG avec logo).
- **Supprimé** : 4 thèmes de couleurs, boutons externes X/WhatsApp/Telegram/LinkedIn, Web Share API, onglet **Intégration Web**, carte HD dégradée.
