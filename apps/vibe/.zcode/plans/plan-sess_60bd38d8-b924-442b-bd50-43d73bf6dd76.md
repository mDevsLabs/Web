# Plan — mAI Vibe : temps réel SSE, audience, IA composer, traduction, modèle défaut, lecteur audio

**Contexte constaté** : backend Deno/Hono (root : `main.ts`, `vibe-*.ts`) + Neon Postgres ; SPA React 19 dans `src/` ; 100 % polling (App.tsx 15s, NotificationsPage 8s, MessagesPage 10s/25s) ; IA = OpenRouter via `MAIAgentFleet.callOpenRouter()` (vibe-mai-fleet.ts:175) ; API TTS complète dans `audio.ts` (`POST /v1/speech`, voix Flux) jamais consommée côté front ; champ `posts.visibility` déjà en base ('public'|'followers'|'private') mais seules les requêtes `= 'public'` existent ; aucun SSE/WebSocket ; pas de limite de caractères (on la garde illimitée).

---

## 1. Temps réel SSE (remplace le polling 15s)

**Backend — nouveau `realtime.ts`** :
- `GET /v1/realtime/stream` (+ alias `/api/vibe`, `/vibe`) via Hono `streamSSE`. Auth : JWT passé en `?token=` (EventSource ne peut pas envoyer de headers) → étendre `extractToken()` (config.ts:290) pour lire le query param. CORS `origin:"*"` déjà en place.
- Table lazy `realtime_events` (id BIGSERIAL, user_id, type, payload JSONB, created_at + index) ; purge des events > 5 min à chaque insert. Fiable même multi-isolates (contrairement à un bus mémoire).
- Boucle : poll interne 1s (`WHERE user_id=$1 AND id > $last`) → push SSE ; heartbeat 15s ; max 2 connexions/utilisateur.
- Types d'événements : `notification` (ligne complète), `unread_counts`, `dm_message`, `dm_typing`, `post_stats` ({post_id, likes/replies/reposts}).
- Émetteurs : `vibe-dms.ts` (envoi DM → `dm_message` + `notification` au destinataire ; nouveau `POST /v1/dms/typing` → `dm_typing` au partenaire), `vibe-users.ts` (insertions notifications existantes → push), `vibe-posts.ts` (like → `post_stats` + notification à l'auteur).

**Frontend** :
- Nouveau `src/services/realtimeService.ts` : singleton EventSource, reconnexion exponentielle, pause si `document.hidden`, rediffuse en `window.dispatchEvent('vibe:realtime', {type, payload})` + maintient les événements existants (`vibe:unread_updated`, `vibe:notification_received`) pour ne rien casser.
- `App.tsx` : intervalle 15s → 60s (filet de sécurité seulement) ; le premier chargement + SSE fait le temps réel.
- `MessagesPage.tsx` : suppression du poll 10s/25s → `dm_message` append + marquage lu ; **indicateur de frappe** « @mathias est en train d'écrire… » (points animés, auto-hide 6s) affiché au-dessus du fil ; `POST /dms/typing` throttlé (2,5s) sur saisie.
- `NotificationsPage.tsx` : suppression du poll 8s → événement `notification`.
- `PostCard.tsx` : abonnement `post_stats` → mise à jour live des compteurs likes/commentaires/reposts des cartes visibles.

## 2. Audience des posts : Public / Abonnés uniquement / Cercle Privé

**Backend** : migration `009` + lazy ensure — table `circle_members` (user_id, member_user_id, PK composite). Routes `GET /v1/circle`, `POST|DELETE /v1/circle/:username`.
- `handleCreatePost` (vibe-posts.ts:537) : accepte `visibility` ∈ public | followers | circle (+'private' = moi seul).
- Lecture : remplacer les filtres `p.visibility = 'public'` (feed, getPost, profil, search, trends) par un prédicat SQL : public, OU (followers ET abonné), OU (circle ET membre du cercle), OU auteur. « Pour Vous »/trends/search restent public-only pour les autres users.
**Frontend** : sélecteur d'audience dans `PostComposer.tsx` (chips Globe/Users/Lock) → `createPost(..., visibility)` (api.ts:325) ; icône d'audience à côté de l'heure dans `PostCard.tsx` ; bouton « Ajouter au cercle » sur `ProfilePage.tsx` + gestion de la liste dans `SettingsPage.tsx`.

## 3. Composer : suggestion IA de continuation (Tab) + actions rapides IA

**Backend** : généraliser l'existant `POST /v1/mai/modulate` (vibe-mai.ts:460) en `POST /v1/ai/text` avec `action` ∈ `complete | fix_spelling | lengthen | shorten | tone` (+ `tone` param). Prompts stricts « réponds uniquement par le texte ». `complete` : max_tokens ~40, renvoie uniquement la suite.

**Frontend `PostComposer.tsx`** :
- **Ghost-text** : div miroir derrière le textarea (typographie identique), continuation proposée en gris zinc-500 ; **Tab** = insérer, Échap = ignorer ; déclenchement debouncé 900 ms après arrêt de saisie (min 8 car.), toggle on/off dans la barre d'outils (économie de quota).
- **Menu IA** (bouton Sparkles existant étendu) : « Corriger l'orthographe », « Allonger », « Réduire », « Changer le ton → (Professionnel / Amical / Humoristique / Direct) » — remplace le brouillon avec undo (état précédent + toast « Annuler »).

## 4. « Traduire avec mAI » (PostCard)

**Backend** : `POST /v1/ai/translate` {post_id, target_lang='fr'} — **un seul appel LLM** : détection de langue + traduction (JSON {detected_language, translation}), modèle par défaut utilisateur. Cache table `post_translations` (post_id, target_lang, translation, detected_language, PK composite) → vues suivantes instantanées, coût amorti.
**Frontend `PostCard.tsx`** : bouton discret « Traduire avec mAI » (icône Languages) sous le texte ; au clic → spinner puis bloc traduction sous le texte d'origine : « Traduit de l'{langue} par mAI » + « Afficher l'original ». La détection est faite par le LLM (pas d'appel par post au simple rendu du fil).

## 5. Modèle mAI par défaut (base de données + API + SettingsPage)

**Backend** : colonnes lazy + migration 009 — `user_settings.mai_default_model` (défaut `poolside/laguna-xs-2.1:free`) et `user_settings.mai_tts_voice` (défaut `flux-alexis-en`). Acceptés dans `handleUpdateSettings` (vibe-settings.ts:84). Helper `getUserDefaultModel(userId)` (cache mémoire 60 s) appliqué partout : `handleMAIChat` (vibe-mai.ts:260), `callOpenRouter` (le défaut gemini figé), suggest-reply DM, et les nouveaux endpoints /ai/text, /ai/translate.
**Frontend** :
- `SettingsPage.tsx` section mAI : select « Modèle mAI par défaut » alimenté par `ApiService.getModels()` (endpoint `/v1/models` existant), + select « Voix de lecture mAI » via `GET /v1/speech/voices`.
- **Sélecteur de modèle rapide** dans l'entête du drawer mAI (MAIDrawer) : change le modèle à la volée et met à jour le réglage en base.

## 6. Lecteur audio flottant « Écouter avec mAI »

**Frontend** (le backend TTS existe déjà : `POST /v1/speech` → mp3) :
- `src/context/AudioPlayerContext.tsx` : file d'attente de segments ({id, title, url}), lecture auto enchaînée, blob cache par post.
- `src/components/feed/FloatingAudioPlayer.tsx` monté dans `App.tsx` (au-dessus de la MobileTabBar) : play/pause, barre de progression, titre (auteur + extrait), vitesse ×1/×1.25, suivant/précédent, fermer.
- `api.ts` : `textToSpeech(text)` → blob URL ; voix = réglage `mai_tts_voice` ; erreur de quota → toast in-app.
- `PostCard.tsx` : bouton « Écouter » (icône Volume2) dans le menu ⋯ → enqueue le post. `PostDetailPage.tsx` : bouton entête « Écouter le fil » → enqueue le post principal puis les commentaires (segments générés séquentiellement → fils longs OK, quota speech progressif).
