## Plan d'amélioration mAI Vibe — 4 fonctionnalités

Contexte : app React 19 + Vite (`src/`), backend Hono sur Deno Deploy (modules `.ts` racine), Postgres Neon, icônes lucide-react. La messagerie a déjà un assistant IA (`POST /api/vibe/dms/generate-reply`, `handleDMGenerateReply` dans `vibe-dms.ts:384`) appelant OpenRouter.

### 1. Presets IA dans les messages (réécrivent le brouillon)
- **Backend `vibe-dms.ts`** : étendre `handleDMGenerateReply` (ou ajouter route `POST /api/vibe/dms/apply-preset`) avec un paramètre `preset` : `shorten` (Réduire), `extend` (Allonger), `tone` (Changer le ton), `improve` (Améliorer), `custom` (utilise un champ `customPrompt`). Chaque preset mappe vers un prompt système spécifique appliqué au brouillon existant (le draft reste requis). Réutiliser le pipeline existant : transcript, cascade de modèles OpenRouter, nettoyage, quota `weekly_usage`, fallback = draft inchangé.
- **Frontend `src/pages/MessagesPage.tsx`** : remplacer/compléter le bouton actuel par un menu « Presets » (icône Sparkles/Wand) listant les 5 presets ; si « Personnalisé », afficher un petit champ de prompt (input inline ou mini-modal) avant d'envoyer. Indicateur de chargement sur la bulle en cours.
- **`src/services/api.ts`** : nouvelle méthode `applyDMReplyPreset(partnerId, draft, preset, customPrompt?)`.

### 2. Notifier des posts d'un compte
- **Backend** : table `post_subscriptions (subscriber_id, author_id, created_at)` (création idempotente, pattern `ensureDMTables`). Routes : `POST /api/vibe/profiles/:username/subscribe` (toggle) + `GET .../subscribe` (état). Dans `vibe-posts.ts`, à la création d'un post (`handleCreatePost`), insérer une notification type `'post'` pour chaque abonné de l'auteur (exclure l'auteur).
- **Types `src/types/vibe.ts`** : ajouter `'post'` au type de notification + icône/rendu dans `NotificationsPage`.
- **Frontend `src/pages/ProfilePage.tsx`** : bouton cloche « Bell » / « BellRing » à côté du bouton Suivre (état optimiste), tooltip « Me notifier de ses posts ». Les badges/toasts existants (polling 15 s dans `App.tsx`) afficheront ces notifications sans changement.

### 3. Suppression de la vidéo d'introduction
- Supprimer le rendu `<IntroBanner />` dans `src/pages/HomePage.tsx:256` (import l.14) et le fichier `src/components/common/IntroBanner.tsx` (le mp4 local reste sur le disque, non référencé — suppression optionnelle).

### 4. Livres (Vibe préférées) — favoris en collections
- **Backend (nouveau module `vibe-books.ts`** enregistré dans `vibe.ts`)** :
  - Tables : `vibe_books (id, user_id, title, icon, created_at)` et `vibe_book_items (book_id, post_id, added_at, PRIMARY KEY(book_id, post_id))`.
  - Routes : `GET /api/vibe/books` (liste + compteurs), `POST /api/vibe/books` (création, refus si l'utilisateur a déjà 5 livres), `PATCH/DELETE /api/vibe/books/:id` (renommer / changer icône / supprimer), `POST /api/vibe/books/:bookId/posts/:postId` (toggle enregistrement), `GET /api/vibe/books/:bookId/posts` (contenu).
- **Frontend** :
  - `PostCard.tsx` : nouveau bouton réaction « Livre » (icône `BookMarked`/`NotebookPen`) → modal listant les Livres existants (avec leur icône) + création rapide d'un nouveau Livre (titre + icône choisie dans un picker lucide) si < 5. Badge visuel si le post est déjà dans un Livre.
  - Nouvelle page `src/pages/BooksPage.tsx` (route `/books`, lazy import dans `App.tsx`) : grille des Livres (icône, titre, nombre de Vibe), vue d'un Livre (`/books/:bookId`) listant ses Vibe (réutilisation du rendu `PostCard`), retrait d'une Vibe, suppression d'un Livre.
  - `Sidebar.tsx` + `MobileTabBar.tsx` : entrée « Livres » (icône `Library`), et corriger au passage l'import manquant `Sparkles` (bug latent signalé).
  - `src/services/api.ts` : méthodes `getBooks`, `createBook`, `updateBook`, `deleteBook`, `toggleBookItem`, `getBookPosts`.

### Ordre d'implémentation
1. Suppression vidéo (trivial) → 2. Presets IA → 3. Notifications de posts → 4. Livres (le plus gros). Build de vérification (`npm run build` / tsc) à la fin de chaque bloc.
