# Modernisation de mAI Vibe — plan d'implémentation

Pile : React 19 + Vite + Tailwind v4 (front `src/`), backend Hono/Deno sur Val Town (`vibe-*.ts`, `auth.ts`, `main.ts`, Postgres Neon). Choix validés : vrai routeur, backend modifiable, priorités = Perf/Algo + UI/UX + Messages/Notifications. La sécurité est incluse en pass allégée (demandée dans le brief initial).

## Phase 1 — Routeur et architecture front
1. Ajouter `react-router-dom` (v7). Routes : `/` (accueil), `/explore`, `/explore/:tab`, `/post/:id`, `/@:username` (+ `/@:username/followers` etc. si déjà géré par ProfilePage), `/messages` (+ `/messages/:convId`), `/notifications`, `/mai`, `/settings`, `/compose` (modale via state + route de secours).
2. Récupérer l'état de `App.tsx` (currentTab, activePostDetailId, activeProfileUsername) : navigation par `<Link>`/`useNavigate`, bouton retour natif, deep-links. Adapter `Sidebar.tsx` et `MobileNav.tsx` (props → NavLink actif).
3. **Code splitting** : `React.lazy` + `Suspense` (fallback squelette) pour toutes les pages sauf Home. Préchargement au survol des liens de la sidebar.
4. Scroll restoration par route (mémoriser la position du fil).

## Phase 2 — Performance
1. **Pagination par curseur backend** (`vibe-posts.ts`, `vibe-dms.ts`) : `?cursor=<published_at>|<id>` sur `/feed`, posts profil, commentaires, conversations, messages ; réponse `{ posts, nextCursor }`. Remplace les LIMIT 40/50 fixes.
2. **Scroll infini** : hook `useInfiniteFeed` (IntersectionObserver sentinelle, garde anti-doublon, état loading/error).
3. Mémoïsation des points chauds : `React.memo` sur PostCard + comparateur, `useCallback` handlers, `useMemo` sur listes dérivées ; virtualisation légère uniquement si nécessaire (probablement inutile avec pagination).
4. Images : `loading="lazy"`, `decoding="async"`, ratio réservé (anti-CLS), fondu au chargement.

## Phase 3 — Algorithme du fil
1. Backend : calcul de score persisté/amélioré — time-decay exponentiel (demi-vie ~18h) sur l'engagement, boost affinité auteur (follows + interactions passées via `post_interactions`), pénalité déjà-vu, diversification (max N posts consécutifs du même auteur).
2. Brancher la pagination sur le classement (fenêtre scorée + curseur stable).
3. Front : onglet « Pour Vous » actualisé avec état « nouveaux posts » (bouton flottant « N nouvelles vibes » au lieu du rafraîchissement brutal), « Suivis » chronologique paginé.

## Phase 4 — UI/UX et animations
1. **Interactions optimistes** : like/repost/bookmark/follow avec rollback sur erreur (hook `useOptimisticToggle`), compteurs animés.
2. Micro-interactions : burst d'animation sur le like (cœur + particules CSS), haptic feedback mobile (`navigator.vibrate`), transitions de page via View Transitions API (fallback fade/slide CSS existant).
3. Squelettes de chargement cohérents (post card, messages, profil) remplaçant les spinners.
4. Mobile : pull-to-refresh sur le fil, geste swipe back (historique routeur), enlarge du composer, safe-areas déjà en place.

## Phase 5 — Messages et notifications
1. Messages : pagination par curseur, polling adaptatif (15s actif → 60s inactif, pause onglet caché — mécanisme existant étendu), envoi optimiste avec état « envoi…/lu », scroll-thread ancré en bas.
2. Notifications : endpoint léger `/notifications/unread_count` (remplace le chargement de toutes les notifs pour les badges, interrogé toutes les 30–60s), regroupement visuel (X a aimé votre post + 4 autres), navigation par deep-link depuis une notification vers le post concerné.

## Phase 6 — Sécurité (pass allégée)
1. CORS strict par allowlist (Vercel + localhost dev) au lieu de l'origine reflétée avec credentials (`main.ts`).
2. Rate limiting simple (map en mémoire) sur auth (OTP), création de posts et messages.
3. Audit XSS : vérifier qu'aucun `dangerouslySetInnerHTML` ne rend du contenu utilisateur non sanitisé (hashtags/mentions/médias).
4. Headers sécurité (CSP de base, X-Content-Type-Options, Referrer-Policy) et expiry JWT réduite à 7j.

## Phase 7 — Vérification
- `tsc -b && vite build` sans erreur, lint oxlint.
- Test manuel des parcours clés (auth, fil, like, commentaire, DM, notif, profil, settings) via le serveur de dev.

Livraison : le backend devra être redéployé sur Val Town après la phase 6 (à ta charge), le front sur Vercel.
